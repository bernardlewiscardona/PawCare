# LOCAL-01 Local-first Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner profile and pets live in an encrypted SQLite database on the phone, behind a
typed data contract that the co-developer's screens call, with the PF-01/PF-02 rules shared with
the parked API through `packages/core`.

**Architecture:**
- `packages/core` holds the pure rules, constants, error codes and a UUIDv7 generator. Both
  `apps/api` and `apps/mobile` use it.
- `apps/mobile/src/data` holds:
  - a small `SqlConnection` interface with two adapters (`expo-sqlite` in the app, `node:sqlite`
    in Vitest);
  - a single-queue `Database` with `BEGIN IMMEDIATE` transactions and change notifications;
  - hand-written migrations, the owner and pet repositories, and a `change_log`;
  - `openPawCareData()`, which handles the key and the open states.
- React wiring (`DataProvider`, `DataGate`, `useLiveQuery`) mounts it in the root layout.

**Tech Stack:** TypeScript, pnpm 10 workspaces, Expo SDK 58 (`expo-sqlite` with SQLCipher,
`expo-secure-store`, `expo-crypto`, `expo-file-system`), Node 22 `node:sqlite`, Vitest 4, NestJS 12
(parked API), `libphonenumber-js`.

**Spec:** `docs/superpowers/specs/2026-11-24-local-first-foundation-design.md` (approved 24 Nov
2026). Read it with this plan. Product rules: `docs/spec/epics/PF.md` (PF-01, PF-02).

## Global Constraints

- **Workflow:**
  - Work on branch `LOCAL-01-local-first`. Commits read `LOCAL-01: <imperative summary>`, use the
    repository identity, and carry no Claude trailers.
  - Local commands need
    `export PATH=/home/bernard/.nvm/versions/node/v22.23.5/bin:$PATH DATABASE_URL='postgresql://pawcare:pawcare_local@localhost:5432/pawcare?schema=public'`
    (the API e2e tests need `pnpm db:up`).
- **Rules and messages:** every rule message is copied verbatim from the current API files
  (`profile-rules.ts`, `pet-rules.ts`, `pets.service.ts`, `owners.service.ts`). Error codes and
  `details` shapes match the API exactly:
  - `VALIDATION_FAILED` → `{ errors: string[], fields: Record<string, string[]> }`;
  - `CONFLICT` → `{ current }`;
  - `NOT_FOUND` → message `Not found`, details `null`.
- **Code conventions:**
  - Core and API are ESM with `.js` relative imports. Mobile uses `@/` for `src/`.
  - Mobile packages are added with `pnpm --filter mobile exec expo install <pkg>`.
  - Tests use `vi.fn()`.
- **SQL:** bound parameters only, never values concatenated into SQL. The one exception is the
  `PRAGMA key` hex literal, which is generated by the app and never comes from input.
- **Logging:** `change_log.fields` and every log line carry field names only. No names,
  microchips, phone numbers, keys or file paths with user data.
- **Weight:**
  - `1 lb = 0.45359237 kg`.
  - Grams are whole numbers, valid when >0 and ≤1,000,000.
  - Kilograms with more than 3 decimals are rejected; pounds are rounded to the gram.
- **The parked API:** its behaviour must not change. Its unit and e2e suites stay green with
  unchanged assertions.
- **Encryption:** a release or development build never opens an unencrypted database. The only
  exception is Expo Go with `__DEV__`, which shows the banner `Development data, not encrypted`.
- **Deletion:** never delete a database file or key. Start fresh renames and copies them instead.

## Review Focus

1. **Hermes without `Intl.supportedValuesOf`.** On a phone whose JS engine lacks it, importing
   core must not crash, and `checkTimeZone` still accepts `Asia/Manila` and rejects `Mars/Base`
   and `GMT+8`. → Task 1 test.
2. **Several IDs in one millisecond.** IDs created within the same millisecond must still sort in
   creation order, because lists page by ID. → Task 1 test.
3. **Long emoji names.** A name of 100 emoji passes the core rule and the SQLite CHECK, and 101
   fails both, because `length()` and `Array.from` must agree. → Task 2 test.
4. **SQLCipher missing from a build.** `encryption-unavailable` must leave no tables and no owner
   row behind and must close the connection, so a later fixed build doesn't find a half-made
   plaintext database. → Task 5 test.
5. **Start fresh with WAL files and an existing key.** The `-wal` and `-shm` files move with the
   database, the old key survives under the retired name, and the new key differs. → Task 5 test.

**Interfaces:**
- Produces:
  - `type SqlValue = string | number | null`.
  - `interface SqlConnection { exec(sql: string): Promise<void>; run(sql: string, params?: SqlValue[]): Promise<{ changes: number }>; get<T>(sql: string, params?: SqlValue[]): Promise<T | undefined>; all<T>(sql: string, params?: SqlValue[]): Promise<T[]>; close(): Promise<void> }`.
  - `type TableName = 'owners' | 'pets' | 'change_log'`; later migrations extend the union.
  - `interface Database { read<T>(fn: (c: SqlConnection) => Promise<T>): Promise<T>; write<T>(tables: readonly TableName[], fn: (c: SqlConnection) => Promise<T>): Promise<T>; subscribe(listener: (tables: ReadonlySet<TableName>) => void): () => void }`.
    - It is created by `createDatabase(connection: SqlConnection): Database`.
    - All calls run one at a time, in call order.
    - `write` runs `BEGIN IMMEDIATE`, then `COMMIT`, or `ROLLBACK` and rethrow on error.
      Listeners are called only after a commit.
    - A failed call never blocks later ones. `write` must not be called from inside `read` or
      `write`, which would deadlock; this is documented on the interface.
  - `interface Migration { version: number; name: string; sql: string }`,
    `MIGRATIONS: readonly Migration[]`, `LATEST_VERSION: number`.
  - `migrate(db: Database): Promise<{ from: number; to: number }>`:
    - It applies each migration whose `version > PRAGMA user_version`, each in its own `write`,
      followed by `PRAGMA user_version = <version>`.
    - It throws `MigrationTooNewError` when `user_version > LATEST_VERSION`.
  - `openNodeConnection(): SqlConnection`: in-memory `DatabaseSync`, with
    `PRAGMA foreign_keys = ON` applied.
- Migration 0001:
  - `owners`:
    - `id TEXT PRIMARY KEY CHECK (length(id) = 36)`.
    - `display_name TEXT` with
      `CHECK (display_name IS NULL OR (length(trim(display_name)) >= 1 AND length(display_name) <= 100))`
      and `CHECK (profile_completed_at IS NULL OR display_name IS NOT NULL)`.
    - `phone TEXT CHECK (phone IS NULL OR length(phone) BETWEEN 1 AND 30)`.
    - `time_zone TEXT NOT NULL DEFAULT 'UTC' CHECK (length(time_zone) BETWEEN 1 AND 64)`.
    - `weight_unit TEXT NOT NULL DEFAULT 'KG' CHECK (weight_unit IN ('KG','LB'))`.
    - `profile_completed_at TEXT`, `created_at TEXT NOT NULL`, `updated_at TEXT NOT NULL`,
      `version INTEGER NOT NULL DEFAULT 1 CHECK (version >= 1)`.
    - `CREATE UNIQUE INDEX owners_single ON owners ((1))`.
  - `pets`:
    - `id`, `owner_id TEXT NOT NULL REFERENCES owners (id)`, `name`, `species`,
      `species_other`, `breed`, `sex DEFAULT 'UNKNOWN'`, `birth_date`,
      `birth_date_estimated INTEGER NOT NULL DEFAULT 0 CHECK (birth_date_estimated IN (0,1))`,
      `current_weight_g INTEGER`, `weight_measured_on`, `microchip`, `archived_at`,
      `created_at`, `updated_at`, `version`.
    - The CHECKs are the PostgreSQL baseline's (`apps/api/prisma/migrations/20261123132746_erd_schema/migration.sql`,
      `pets_*_check`) with `char_length`/`btrim` → `length`/`trim`, enum CHECKs on `species` and
      `sex`, `current_weight_g > 0 AND <= 1000000`, and `date(x) = x` on both date columns.
    - `UNIQUE (owner_id, id)`, and `CREATE INDEX pets_owner_archived ON pets (owner_id, archived_at)`.
  - `change_log`:
    - `id`, `owner_id NOT NULL REFERENCES owners (id)`,
      `entity_type TEXT NOT NULL CHECK (entity_type IN ('owner','pet'))`, `entity_id`,
      `entity_version INTEGER NOT NULL`, `action TEXT NOT NULL`,
      `fields TEXT NOT NULL CHECK (json_valid(fields))`, `occurred_at TEXT NOT NULL`.
    - Triggers `change_log_no_update` and `change_log_no_delete` `RAISE(ABORT, 'change_log is append-only')`.

`create` mirrors `PetsService.create` and `normalizePet`, minus the Idempotency-Key:
- **Setup first:** without a finished profile it throws `profileSetupRequired()` (message
  `Finish setting up your profile before adding a pet.`).
- **Today** is `localDate(owner.time_zone, deps.now())`.
- **Errors:** all type and rule errors come back in one `VALIDATION_FAILED`, with every
  `weight.*` error under `weight`.
- **Type messages:** a missing or non-string `name` → `REQUIRED`/`INVALID`. A bad `species` →
  `CHOOSE_SPECIES` and a bad `sex` → `CHOOSE_SEX`. A `weight` that isn't `{ value: finite number, unit }`
  → `WEIGHT_NUMBER` or `CHOOSE_UNIT` under `weight`.
- **Measurement date** defaults to today when a weight is given.
- **History:** `change_log` `pet.created`, `fields` = keys of the normalised input.

`list`:
- `limit` must be an integer within `PAGE_LIMIT`, otherwise `Choose a page size of 1–100.`
- `cursor` must be a UUID, otherwise `Use the nextCursor from the previous page.`
- It returns active pets (`archived_at IS NULL`) with `id > cursor`, `ORDER BY id`, taking
  `limit + 1` rows.

`get`: a non-UUID or unknown ID → `notFound()`. Archived pets are returned.

**Interfaces:**
- Consumes: Tasks 2–4 (`createDatabase`, `migrate`, `LATEST_VERSION`, `MigrationTooNewError`,
  `ensureOwner`, the repository factories, `createUuidV7`).
- Produces:
  - `interface OpenEnv`:
    - `isExpoGo: boolean; isDev: boolean;`
    - `keys: { get(name: string): Promise<string | null>; set(name: string, value: string): Promise<void> };`
    - `files: { exists(name: string): Promise<boolean>; rename(from: string, to: string): Promise<void> };`
    - `connect(name: string): Promise<SqlConnection>;`
    - `randomBytes(n: number): Uint8Array; now(): Date;`
  - `interface PawCareData { owner: OwnerRepository; pets: PetRepository; subscribe: Database['subscribe']; close(): Promise<void> }`.
  - `type OpenResult` is one of:
    - `{ state: 'ready'; encrypted: boolean; userVersion: number; data: PawCareData }`
    - `{ state: 'encryption-unavailable' }`
    - `{ state: 'too-new' }`
    - `{ state: 'key-missing'; startFresh(): Promise<OpenResult> }`
    - `{ state: 'failed'; startFresh(): Promise<OpenResult>; retry(): Promise<OpenResult> }`
  - `openPawCareData(env: OpenEnv): Promise<OpenResult>`.
  - Constants: `DB_NAME = 'pawcare.db'`, `KEY_NAME = 'pawcare-db-key'`.
  - `expoOpenEnv(): OpenEnv`:
    - `isExpoGo` is `Constants.executionEnvironment === ExecutionEnvironment.StoreClient`, and
      `isDev` is `__DEV__`.
    - `keys` uses SecureStore with `keychainAccessible: WHEN_UNLOCKED_THIS_DEVICE_ONLY`.
    - `files` works under `SQLite.defaultDatabaseDirectory`.
    - `connect` uses `openDatabaseAsync`, and `randomBytes` uses `Crypto.getRandomBytes`.
    - Check the SDK 58 docs for the `expo-file-system` rename API.
  - `index.ts` re-exports the public types: `DataError`, `OwnerProfile`, `UpdateOwnerInput`,
    `Pet`, `CreatePetInput`, `PetPage`, `OpenResult`, `PawCareData`, `TableName`. Task 6 adds the
    React exports.

Open sequence (the order matters):
1. `encrypted = !(env.isExpoGo && env.isDev)`.
2. When encrypted:
   1. If `keys.get(KEY_NAME)` is null and `files.exists(DB_NAME)`, return `key-missing`.
   2. If there is no key, create one from 32 `randomBytes`, as lowercase hex, and `set` it.
3. `connect(DB_NAME)`.
4. When encrypted:
   1. `exec("PRAGMA key = \"x'<hex>'\"")`.
   2. `get('PRAGMA cipher_version')`. If it returns no row, `close()` and return
      `encryption-unavailable`, running nothing else.
5. `exec('PRAGMA foreign_keys = ON')`, then read `PRAGMA user_version`. A wrong key throws here,
   which leads to `failed`.
6. `migrate`. `MigrationTooNewError` → `close()` and return `too-new`.
7. `ensureOwner` in a `write(['owners','change_log'])`.
8. Return `ready`.
9. Any other error: `close()` where possible, then `console.warn('[data] open failed at <step>:', error.name)`.
   Never log the message, path or key. Return `failed`.

`startFresh()`:
1. Build a stamp from `now()` (`YYYYMMDDTHHmmssSSSZ`).
2. For `''`, `-wal` and `-shm`, rename `pawcare.db<suffix>` to `pawcare-<stamp>.retired.db<suffix>`
   when the file exists.
3. If a key exists, copy it to `pawcare-db-key-<stamp>`.
4. Write a new key to `KEY_NAME`.
5. Run the open sequence again. Nothing is deleted.

`retry()` runs the open sequence again unchanged.
